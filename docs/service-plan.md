# 실시간 야구 팬덤 대결 서비스

**슬로건: “경기는 선수들이, 신경전은 팬들이!”**

## 1. 서비스 개요

야구 중계를 시청하면서 다음 타석의 결과를 예측하고, 정답을 맞혀 얻은 포인트로 상대팀 팬들에게 유쾌한 도발을 보내는 **실시간 참여형 모바일 웹 서비스**.

기존 스포츠 중계가 수동적인 관람이라면, 이 서비스는 팬들이 경기의 매 순간에 참여하고 서로 경쟁하도록 만든다.

**핵심 가치**

- 경기를 보는 동안 지속적으로 참여할 거리 제공
- 예측 성공에 따른 성취감과 보상
- 양 팀 팬덤 사이의 유쾌한 경쟁
- 별도 앱 설치 없이 모바일 웹으로 즉시 참여

## 2. 핵심 사용자 경험

### ① 응원팀 선택

사용자가 경기 목록에서 경기를 선택하고 자신이 응원하는 팀을 지정한다.

예시: LG 트윈스 vs 두산 베어스

### ② 실시간 예측

현재 타석의 결과를 예측한다.

**이번 타자, 출루할까?**

- 출루한다
- 아웃된다

투표 결과는 실시간 비율로 표시한다. 타석 결과가 나오기 전 투표를 마감한다.

### ③ 포인트 획득

예측이 적중하면 게임 내 포인트를 지급한다.

- 정답: +100P
- 오답: 0P
- 포인트 베팅 및 차감 없음
- 연속 적중 기록 표시 가능

포인트는 현금이나 상품으로 교환할 수 없으며, 서비스 내부 도발 기능에만 사용한다.

### ④ 상대 팬덤 도발

획득한 포인트를 소비해 상대팀 팬에게 도발 카드를 전송한다.

**도발 문구 예시**

- KIA: “호랑이인 줄 알았는데 종이호랑이?”
- LG: “오늘은 쌍둥이로 아웃 두 개?”
- 두산: “곰이 아니라 겨울잠 자는 중?”
- 롯데: “올해는 진짜 가을야구 한다며?”
- 한화: “독수리 날개는 어디 두고 왔어?”

도발은 사전 제작된 문구·이미지만 사용한다. 자유 입력, 욕설, 선수 개인 비하, 지역 비하 등은 허용하지 않는다.

### ⑤ 도발 수신 및 반격

도발 대상은 상대팀의 실제 활동 사용자 중 선정한다.

- 최근 3분 이내 투표한 사용자 우선
- 화면을 보고 있는 사용자에게 우선 노출
- 비활성 사용자 제외
- 동일 사용자에게 반복 도발이 집중되지 않도록 제한

도발받은 팬은 다음 예측을 맞혀 포인트를 얻고 반격할 수 있다.

## 4. 경기 데이터 처리

### 해커톤 데모

과거 KBO 경기의 타석별 데이터를 이용해 실제 경기처럼 재생한다.

**진행 흐름**

과거 경기 데이터 로딩\
↓\
타자 등장\
↓\
예측 투표 시작\
↓\
투표 마감\
↓\
실제 타석 결과 공개\
↓\
정답 판정 및 포인트 지급\
↓\
다음 타석 진행

타석당 약 15\~20초로 압축해 시연한다.

출루·아웃 이외의 타석 결과는 사전에 판정 규칙을 정의한다. 예를 들어 희생플라이, 실책 출루, 야수선택 등을 어떻게 처리할지 명확히 해야 한다.

### 정식 서비스

실제 경기 데이터 API를 연결해 자동으로 타석 시작과 종료를 감지한다.

**검토 대상**

- Sportradar: KBO 실시간 이벤트 데이터 제공
- 네이버 스포츠: 경기별 상세 데이터 활용 가능성 검토

단, 실제 API 접근 권한, 라이선스, 지연 시간, 지원 범위는 별도 검증이 필요하다.

데모와 실시간 운영에서 동일한 이벤트 처리 구조를 재사용하도록 설계한다.

## 5. 기술 구성

**플랫폼:** 모바일 웹

**권장 기술**

- Frontend: Next.js
- Backend / DB: Supabase
- 실시간 동기화: Supabase Realtime
- 배포: Vercel
- 경기 데이터: 과거 KBO 타석별 기록

### 주요 데이터

- 사용자: 익명 ID, 응원팀, 포인트
- 경기: 경기 ID, 양 팀, 현재 이닝·타석
- 예측: 사용자, 타석 ID, 선택, 정답 여부
- 도발: 발신자, 수신자, 카드 종류, 소비 포인트
- 활동 상태: 마지막 투표 시각, 화면 활성 여부

투표 마감과 정답 판정은 서버에서 처리하며, 포인트 중복 지급을 방지한다.

## 6. 4시간 해커톤 개발 계획

| 시간     | 개발 목표                         |
| ------ | ----------------------------- |
| 0\~1시간 | 화면 구조, DB, 과거 경기 데이터 준비       |
| 1\~2시간 | 경기 리플레이 및 실시간 투표              |
| 2\~3시간 | 정답 판정, 포인트, 도발 카드             |
| 3\~4시간 | 다중 사용자 테스트, UI 개선, 배포 및 발표 준비 |

**MVP 범위**

한 경기, 두 팀, 출루·아웃 예측, 포인트 지급, 기본 도발 카드에 집중한다.

회원가입, 실제 결제, 전체 KBO 경기 지원, 자유 채팅, 복잡한 랭킹 시스템은 제외한다.

## 7. 현장 시연 시나리오

1. 참가자들이 QR코드로 모바일 웹 접속
2. LG 또는 두산 응원팀 선택
3. 과거 경기 리플레이 시작
4. 현재 타석에 대한 예측 투표
5. 실제 결과 공개 및 포인트 지급
6. 정답을 맞힌 팬이 도발 카드 구매
7. 상대팀 팬들의 화면에 도발 연출
8. 다음 타석에서 반격

**시연의 핵심:** 여러 명이 동시에 참여하면서 실제로 웃고 경쟁하는 모습을 보여주는 것.

## 8. 사업성 및 확장 가능성

### 유입

- 경기 중 QR코드·링크 공유
- 응원팀별 팬덤 참여
- 친구와 함께 예측 대결

### 재방문

- KBO 정규시즌 경기마다 새로운 예측
- 포인트 및 누적 적중 기록
- 팀별 경쟁과 도발·반격

### 확장

- 다양한 예측 유형 추가
- 팀별 도발 이미지·애니메이션 확대
- 개인·팬덤별 시즌 랭킹
- 다른 스포츠 종목으로 확대
- 스포츠 커뮤니티 및 중계 서비스와 연계

## 10. 해커톤 성공 기준

- 여러 사용자가 서로 다른 팀으로 동시에 접속 가능
- 타석별 투표가 정상적으로 집계됨
- 경기 결과에 따라 포인트가 정확하게 지급됨
- 도발이 실제 상대팀 활성 사용자에게 전달됨
- 시연 참여자가 추가 투표와 반격에 자발적으로 참여함
